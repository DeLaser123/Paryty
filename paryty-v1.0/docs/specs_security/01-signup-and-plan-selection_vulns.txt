VULN-01-001 | Cookie Secure Flag Is Variable (Conditionally Absent)
Severity: MEDIUM
Pre-state:  spec calls for "HttpOnly, SameSite=Strict, conditional Secure"
Post-state: auth_rest_adapter.go uses `Secure: a.cookieSecure` where cookieSecure
            is `os.Getenv("PARYTY_DEV_MODE") != "true"`
Evidence:   semgrep-go found 6 cookie-missing-secure warnings at lines 199,205,212,218
            in cluster/internal/auth/auth_rest_adapter.go
Analysis:   In dev mode (PARYTY_DEV_MODE=true), cookies are sent without Secure flag.
            This is intentional for local HTTP development but means ANY deployment
            without PARYTY_DEV_MODE explictly set to "true" WILL get Secure cookies.
            However, if PARYTY_DEV_MODE is not set at all (empty string), cookieSecure
            defaults to true — so production behavior is correct. The risk is that
            manual deployments might accidentally run in dev mode.
Reproduce:  Set PARYTY_DEV_MODE=true, start cluster, register — observe cookies lack
            Secure flag (visible in browser DevTools > Application > Cookies).
Mitigation: FALSE POSITIVE for production. Acceptable for dev. Recommend adding
            explicit env guard: `if os.Getenv("PARYTY_DEV_MODE") == ""` before
            production deployment scripts.

VULN-01-002 | Registration Rate Limiter Uses ClientIP (IP Spoofing Possible)
Severity: MEDIUM
Pre-state:  spec spec section 2.1 mentions rate limiting BE-01
Post-state: handler.go implements registerRateLimiter using c.ClientIP() in
            auth_rest_adapter.go:67
Evidence:   Code review of auth_rest_adapter.go Register handler
Analysis:   `c.ClientIP()` trusts X-Forwarded-For/X-Real-IP headers by default
            in Gin. An attacker can spoof their IP via these headers, bypassing
            the 5/hour/IP rate limit. Proxy/CDN deployments need trusted proxy
            configuration (`router.SetTrustedProxies()` / `router.ForwardedByClientIP`).
Reproduce:  curl -H "X-Forwarded-For: 10.0.0.1" -X POST /api/v1/auth/register -d '{...}'
            Repeat 5 times. Then change X-Forwarded-For to 10.0.0.2. Register
            successfully — bypassing rate limit.
Mitigation: Configure Gin trusted proxies in main.go. For dev: not exploitable
            without a reverse proxy trusting external headers.

VULN-01-003 | esbuild Dev Server Accessible (npm dependency)
Severity: MODERATE
Pre-state:  package.json includes vite which depends on esbuild
Post-state: Same
Evidence:   npm audit: GHSA-67mh-4wv8-2f99 — esbuild <=0.24.2 allows any website to
            send requests to the dev server and read responses
Reproduce:  Start `npm run dev`, navigate to localhost:3000. esbuild dev server
            will accept cross-origin requests from any website.
Mitigation: Upgrade vite to >=8.0.16 (npm audit fix --force). Not exploitable in
            production (production builds don't use dev server).
